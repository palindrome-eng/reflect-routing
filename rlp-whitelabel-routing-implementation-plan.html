2. The two products, in routing terms

2.1 Whitelabel (proxy) - "lending-shaped", the easy one

Branded stablecoins over USDC+. Each integrator market is one ProxyState PDA (["proxy", branded_mint], 115 bytes, no discriminator) holding a (branded_mint, stablecoin_mint) pair plus a fee and principal bookkeeping. Exactly two routable ops per market, dispatched by input mint alone, exactly like lending:

  • wrap: stablecoin (USDC+) → branded tokens. ERC4626-style share mint with virtual offsets (1_000_000 each side).
  • unwrap: branded tokens → stablecoin. Same math inverted.

Both ops run a yield crank first (value the vault at the oracle price, split realized interest into principal vs integrator commission by fee bps), then price the user's share against the CRANKED principal. The SDK quotes mirror this exactly; the venue only delegates. Oracle staleness gate: 200 slots (slot-based, unlike rlp's 120 seconds). There are NO caps, NO floors, NO pause flags on this product - the only quote-time failure that maps to an on-chain revert is a stale oracle.

The protocol-level USDC ↔ USDC+ stable-swap (1 bps fee, program-owned inventory) is a SEPARATE facility, not part of any branded market. It becomes its own small venue in Phase F. claim_fees is an integrator-admin op, never routable - ignore it.

2.2 RLP (insurance) - "bonds-shaped", with three twists

One LiquidityPool (u8-indexed PDA) holding N registered assets (each an SPL mint bound to a Pyth or Switchboard oracle), issuing one LP token against the pool's total USD value. Routable edges:

  • restake: asset → LP token. lp_out = deposit_usd / pool_usd * lp_supply (1:1 with USD on an empty pool).
  • swap: asset → asset at the raw oracle cross-rate, no fee.
  • LP → asset is NOT routable: withdrawal is a two-transaction cooldown (request_withdrawal, then withdraw after maturation, paying a pro-rata multi-asset basket). Out of scope for aggregator routing; quote must refuse it.

The three twists vs bonds:

  1. Asset discovery needs out-of-band input. Settings stores only the asset COUNT. The registered mints come from a one-time gPA scan (Asset discriminator, dataSize 74) done by whoever lists the market, and are injected into the venue at construction (decision D5).
  2. The SDK quote is deliberately thin. It does NOT check the killswitch/frozen flags, does NOT check swap output liquidity, and does NOT respect asset access levels. The venue must add these three guards itself or quote==execution breaks (decision D6).
  3. Single deployment. All rlp PDAs derive against the const ids::RLP_PROGRAM. Same for proxy against proxy::ids::PROGRAM. Unlike strategy, nothing is program-id-relative (decision D3).

3. Locked design decisions

#DecisionRationale / rejected alternative
D1 Venue cores stay concrete, no trait: core/src/whitelabel.rs::WhitelabelVenue, core/src/rlp.rs::RlpVenue, core/src/whitelabel.rs::WhitelabelSwapVenue, mirroring LendingVenue/BondVenue. The generic ReflectRoutingVenue trait was already explored and REJECTED when the core crate was extracted. Do not resurrect it.
D2 Market account per product: whitelabel = the ProxyState PDA; rlp = the LiquidityPool PDA; whitelabel-swap = the pinned ORACLE account. Both are gPA-enumerable, owned by the product program (except the swap oracle, see D3), and stable. The branded mint alone was rejected as the whitelabel market key because aggregators list an existing account they can fetch, and ProxyState is that account.
D3 Program ids are pinned, not owner-derived: reflect_sdk::proxy::ids::PROGRAM and reflect_sdk::rlp::ids::RLP_PROGRAM. from_market takes only the market key. The venue verifies at load() time that the market account's owner equals the pinned id (whitelabel/rlp) and errors otherwise. LiteSVM tests deploy the real program at the REAL address. Lending/bonds are program-id-relative because strategy::pda takes a program id; the rlp/proxy SDK modules derive every PDA against the const, so a mock program id is impossible anyway. The oracle-keyed swap venue skips the owner check (its market account is owned by the price program, verified fact).
D4 Venue quote error mapping (all three venues): amount == 0 ⇒ Ok(Some(zero)) before touching state; CoreError::StaleOracle ⇒ Ok(None) (no route); every other CoreError ⇒ Err. rlp/proxy quotes never set would_revert (they surface CoreError instead - verified in common/action.rs docs). A stale oracle IS a predicted on-chain revert, so it must be "no route", not an adapter error; a malformed account or unknown mint is a hard error, matching the lending/bonds "no route > bad route > loud error" ladder.
D5 RLP asset set is injected at construction: RlpVenue::from_market(market, asset_mints: Vec<Pubkey>). Oracle bindings are NOT injected; the venue derives derive_asset(mint) PDAs, fetches them through the normal account handshake, and decodes OracleRefs itself via decode_asset_mint_and_oracle. Jupiter carries the mint list in KeyedAccount.params (restoring the upstream field, see Phase D); Titan gets a dedicated constructor and its FromAccount impl returns a clear error. Verified: no fetchable account lists the mints, and neither aggregator host can gPA. Injecting mints only (not oracles) keeps the injected config minimal and self-healing - oracle rebindings are picked up from chain. A compiled-in asset list was rejected (registry changes, devnet vs mainnet drift).
D6 RlpVenue adds three quote guards the SDK deliberately omits: (a) Settings.frozen() / killswitch per action (Restake=0, PublicSwap=3); (b) swap output clamped by the destination pool vault balance (amount_out > to_vault.amount ⇒ no route); (c) assets with access_level == Private (1) are excluded from mints() entirely. All three return Ok(None), never a fake number. Each is an on-chain revert the SDK quote would happily quote through. The Titan bounds() binary search and the atom-exact parity bar both require quote totality AND honesty.
D7 Staleness-guard mismatch is accepted: rlp's registered-asset count is cross-checked against Settings.assets() at load; a mismatch (admin added/removed an asset since the listing scan) fails load() loudly. A restake built with too few remaining-account triples reverts on-chain. Failing load is the only honest option; the lister re-scans and re-lists.
D8 Jupiter Swap tags: ReflectProxyWrap, ReflectProxyUnwrap, ReflectRlpRestake, ReflectRlpSwap (+ ReflectProxySwap in Phase F), appended as placeholders exactly like the bonds tags: NOT wire-stable, pending Jupiter's cross-org assignment. Wrap and unwrap use the SAME 8-meta account order (verified in proxy/ix.rs) - direction lives only in the data discriminator, so a single tag with direction-from-account-order (the lending trick) is IMPOSSIBLE here. Two tags are mandatory.
D9 RouteQuote.fee is always 0 for both products. Proxy's crank fee is folded into pricing (never a scalar); rlp charges no routable-op fee. Same reasoning as bonds: a wrong-unit fee misleads the router more than zero does.
D10 Parity strategy: whitelabel = dump the LIVE mainnet .so (cache, gitignore, skip offline - the Kamino pattern) + hand-synthesized state; rlp = build the program from local Anchor source + initialize state in LiteSVM by driving the SDK's own rlp::ix::admin builders. No cross-repo Mollusk forge needed for either. Unlike lending (Kamino obligations only a program can create), ALL state for both products is either hand-synthesizable (proxy: 115-byte state, 17-byte oracle, SPL accounts) or creatable through the program's own admin instructions (rlp). The devnet rlp binary is stale (verified) and must not be used.
D11 Withdrawal (LP → asset), request_withdrawal, claim_fees, and all crank/admin ops are OUT OF SCOPE for routing. Two-transaction cooldown flows and admin ops are not aggregator edges. quote_by_mints already rejects LP-as-input with CoreError::InvalidData.

Proxy quirks that matter
  • Staleness is slot-based (200 slots). Only clock.slot matters, but populate both fields.
  • quote_wrap(0)/quote_unwrap(0) return Ok(0) - no ZeroAmount error - but the venue still early-returns at 0 so the contract holds on a COLD venue.
  • Handle verbs reject slippage_bps > 10_000 with InvalidData (not clamped).
  • Everything is classic SPL Token. No Token-2022 anywhere in this product.
  • all_keys() is 4 keys; stablecoin_mint is in the struct but NOT fetched by default. The venue appends it for decimals.

RLP quirks that matter
  • Staleness is unix-time-based: reject if publish_time + 120 < clock.unix. Only clock.unix matters for rlp quotes.
  • The SDK swap quote reads ONLY the two oracles - it does not check the destination vault balance (guard D6b).
  • The SDK checks neither Settings.frozen() nor the killswitch (guard D6a) nor asset access levels (guard D6c).
  • Restake pool valuation covers EVERY registered asset - the account set and the built instruction's remaining accounts are per-asset triples; a stale asset list reverts on-chain (guard D7).
  • Everything is classic SPL Token.
  • Pyth oracles must be PriceUpdateV2 with verification level Full; Switchboard is the legacy aggregator layout.

6.2 Methods (exact contracts)

MethodContract
from_market(market: Pubkey) -> Self Cold constructor. NO owner param (decision D3). program_id() returns ids::PROGRAM.
seeds(&self) -> Vec<Pubkey> vec![self.market]. ONE seed - the ProxyState itself carries both mints.
discovery_keys(&self, proxy_state: &[u8]) -> Result<Vec<Pubkey>> Decode ProxyState::from_bytes (surface decode errors, do not treat as cold). Read branded_mint/stablecoin_mint. No canonical-PDA guard: the SDK loader re-derives ["proxy", branded] itself and load() fails on a mismatch (proxy/accounts.rs:64-65). Return quote_account_keys_from_state(branded, proxy_state)?.all_keys() PLUS the stablecoin mint account key appended (needed for decimals; extra keys pass through the loader harmlessly). 5 keys total.
load(&mut self, accounts: impl IntoIterator<Item = (Pubkey, Pubkey, Vec<u8>)>) -> Result<()> Same item shape as the other venues (key, owner, data). Guard: find the market account in the iterator and check its owner is ids::PROGRAM, else error. Extract branded_mint from the market bytes, then build WhitelabelAccounts::from_account_map(branded, accounts.map(|(k, _, d)| (k, d))) and cache behind Arc. Decode both mint accounts (SPL Mint: decimals at byte 44) into MintInfo { pubkey, decimals, token_program: TOKEN_PROGRAM } - this product is SPL-only. Missing/short mint account bytes are an error (a proxy market always has both mints).
mints(&self) -> Vec<MintInfo> [stablecoin (idx 0), branded (idx 1)] - deposit-then-receipt order, mirroring lending's [deposit, receipt]. Empty until loaded.
route(&self, input_mint) -> Result<WhitelabelRoute> input == stablecoin => Wrap, input == branded => Unwrap, else error. Exposed for the Jupiter tag pick (bonds precedent).
quote(&self, input_mint, amount, clock) -> Result<Option<RouteQuote>> amount == 0 ⇒ Ok(Some(RouteQuote { amount_out: 0, fee: 0 })) BEFORE touching loaded. Then delegate to accounts.quote_by_mints(input_mint, amount, clock) and apply the D4 ladder: Err(CoreError::StaleOracle) ⇒ Ok(None); other Err ⇒ Err; Ok(q) ⇒ Ok(Some(RouteQuote { amount_out: q.amount_out, fee: 0 })) (D9).
build(&self, user, input_mint, amount, slippage_bps, clock) -> Result<Instruction> Classify via route(), then accounts.whitelabel(user).wrap(amount, slippage_bps, clock) or .unwrap(...), return built.instruction. Build with the REQUEST amount, not the quote (vendored-trait rule). No headroom param - unwrap output is exact, not an upper bound like lending redeem.
CoreError matching CoreError lives at reflect_protocol_core::primitives::error::CoreError. If it is not re-exported at reflect_sdk::proxy/rlp level, add it to the Phase 0 seam PR (pub use reflect_protocol_core::primitives::error::CoreError; in each module or in common). The D4 ladder needs to match on CoreError::StaleOracle by value, not by string.

7.2 The three-round discovery handshake

The venue cannot produce the full fetch set in one derivation (oracle keys live inside the Asset PDA bytes), so discovery_keys is TWO-STAGE on top of the seeds. Both aggregator shims already loop update cycles until the venue warms (Jupiter re-calls get_accounts_to_update/update; Titan's update_state can do multiple cache.get_accounts rounds internally), so this costs one extra cycle vs bonds, nothing structural.

RoundKeysDerivable from
1 - seeds() [market, derive_settings().0] ++ derive_asset(mint).0 for every injected mint ++ the mint accounts themselves The injected mint list alone. Asset PDAs and mint accounts (decimals) need no fetched bytes.
2 - discovery_keys(pool_bytes, settings_bytes, asset_bytes: &[&[u8]]) Everything above PLUS [lp_token mint] ++ per-asset [token_ata(pool, mint), oracle_key(oracle)] (i.e. pool_discovery_keys(index, lp_token, &assets) output, deduped with round 1) index + lp_token from LiquidityPoolView; per-asset OracleRef from decode_asset_mint_and_oracle on each Asset PDA's bytes.
3 - load(all fetched accounts) Build PoolAccounts::from_account_map(index, assets, ...), run the load-time guards, cache everything.

MethodContract
from_market(market: Pubkey, asset_mints: Vec<Pubkey>) -> Self Cold constructor. The mint list comes from the lister's one-time gPA scan (see 7.5). program_id() returns ids::RLP_PROGRAM.
seeds(&self) -> Vec<Pubkey> Round-1 set above, in a FIXED order the shim relies on: [market, settings, asset_pda_0.., mint_0..].

14.4 Quote math (for eyeballing parity failures)

// proxy (all floor; VIRT = 1_000_000 on both sides; price fixed-point 10^precision)
crank:  interest = sat(vault_usd - (principal + commission));  commission += floor(interest * fee_bps / 10_000); principal += rest
wrap:   usd = floor(amount * price / 10^prec);  branded_out = floor(usd * (supply + VIRT) / (principal' + VIRT))
unwrap: usd = floor(amount * (principal' + VIRT) / (supply + VIRT));  out = floor(usd * 10^prec / price)
swap:   usdc->usdc+ : floor(amount * 10^prec * 9_999 / price / 10_000);  reverse: floor(amount * price * 9_999 / 10_000 / 10^prec)

// rlp
restake: lp_out = deposit_usd / pool_usd_total * lp_supply   (1:1 with USD on empty pool)
swap:    out = amount_in * price_from / price_to             (oracle cross-rate, no fee)
staleness: publish_time + 120 < clock.unix => StaleOracle
